Önce aşağıdaki source-of-truth dosyalarını oku:

- PROJECT.md
- docs/ANALIZ.md
- docs/TEKNIK_MIMARI_TASLAK.md

Ardından mevcut Flutter `mobile/` yapısını ve backend Budget + Category endpoint sözleşmelerini incele.

Bu görevde yalnızca Flutter Budget entegrasyonunu geliştir.

Mevcut Authentication, ApiClient, secure storage, Dashboard, Transactions, navigation ve theme yapısını koru.

Bu aşamada Bill entegrasyonuna geçme.

## Amaç

Flutter uygulamasındaki Bütçeler ekranını gerçek backend Budget endpointleriyle çalışır hale getirmek.

Kullanıcı:

- seçili ay/yıldaki bütçelerini görebilmeli,
- yeni bütçe oluşturabilmeli,
- yalnızca bütçe limitini güncelleyebilmeli,
- bütçe kaydını silebilmeli,
- harcanan tutarı,
- kullanım yüzdesini,
- Normal / Warning / Exceeded durumunu

backend tarafından hesaplanan değerlerden görebilmelidir.

Flutter finansal bütçe hesabı yapmamalıdır.

---

## 1. Backend sözleşmesini doğrudan incele

Aşağıdaki backend dosyalarını incele:

- BudgetsController
- BudgetService
- Budget DTO'ları
- BudgetAlertStatus
- Category DTO'ları
- CategoriesController

JSON field isimlerini tahmin etme.

Flutter model ve request yapılarını backend DTO'larıyla birebir uyumlu oluştur.

Backend kodunu değiştirme.

---

## 2. Budget modelleri

Flutter tarafında backend sözleşmesine uygun modeller oluştur.

En az:

- CreateBudgetRequest
- UpdateBudgetRequest
- BudgetResponse / BudgetListItem eşdeğeri
- BudgetAlertStatus eşlemesi

gerekir.

Known backend alanları:

- Id
- Category
- LimitAmount
- Month
- Year
- SpentAmount
- UsagePercent
- AlertStatus
- CreatedAt

Category entity'sini mobile taşıma.
Backend response DTO'sunu temsil eden sade model kullan.

---

## 3. CreateBudgetRequest

Request yalnızca backend DTO alanlarını içermelidir:

- CategoryId
- LimitAmount
- Month
- Year

UserId bulunmamalıdır.

Kurallar:

- LimitAmount > 0
- Month 1–12
- Year 2000–2100
- CategoryId backend category listesinden seçilmelidir

---

## 4. UpdateBudgetRequest

Backend sözleşmesi gereği yalnızca:

- LimitAmount

içermelidir.

Flutter update request içine:

- CategoryId
- Month
- Year
- UserId

eklememelidir.

---

## 5. BudgetService

Flutter tarafında sade BudgetService oluştur.

Mevcut ApiClient'i kullan.

Endpointler:

- `GET /api/budgets`
- `POST /api/budgets`
- `PUT /api/budgets/{id}`
- `DELETE /api/budgets/{id}`

Backend'de olmayan detail endpointi ekleme.

Sorumluluklar:

- list
- create
- update limit
- delete
- response parse
- kontrollü hata aktarımı

---

## 6. CategoryService'i yeniden kullan

Mevcut Transactions aşamasında oluşturulan CategoryService'i kullan.

İkinci bir category API servisi oluşturma.

Yeni bütçe oluştururken Category dropdown/select backend category listesinden gelmelidir.

## 8. İlk yükleme

Bütçeler ekranı açıldığında:

`GET /api/budgets`

çağrısı yapılmalıdır.

Backend kullanıcının tüm Budget kayıtlarını döndürüyorsa Flutter bunları selected Month/Year için presentation amacıyla filtreleyebilir.

Bu filtre yalnızca liste sunumu içindir.

SpentAmount, UsagePercent veya AlertStatus Flutter tarafından yeniden hesaplanmamalıdır.

## 9. Ay/yıl seçimi

Ekranın üst kısmında sade bir period selector bulunmalıdır.

Dashboard ile mümkün olduğunca aynı tasarım/UX yaklaşımını kullan.

Kullanıcı:

- Month 1–12
- Year 2000–2100

arasında seçim yapabilmelidir.

İlk dönem için mümkünse mevcut backend Budget kayıtlarından veya Europe/Istanbul kullanıcı deneyimiyle uyumlu mevcut ay/yıl kullanılabilir.

Ancak bunun için finansal hesap yapma.

UI dönem seçimi yalnızca hangi Budget kayıtlarının gösterileceğini belirler.

---

## 10. Bütçe listesi

Seçili ay/yıla ait bütçeler kart halinde gösterilmelidir.

Her kartta:

- Category name
- LimitAmount
- SpentAmount
- UsagePercent
- AlertStatus

göster.

İstersen kalan tutarı görsel olarak göstermek için:

LimitAmount - SpentAmount

hesabını yapma.

Source-of-truth dokümanda finansal hesapların backend'de kalması ilkesi nedeniyle, backend response'ta RemainingAmount yoksa mobilde yeni finansal değer üretme.

Yalnızca backend'in verdiği alanları göster.

---

## 11. UsagePercent

Backend UsagePercent değerini doğrudan göster.

Flutter tekrar hesaplamamalıdır.

Örnek:

Backend `%135` döndürürse:

- text `%135`
- progress bar maksimum genişlikte

olabilir.

Progress indicator render değeri clamp edilebilir.

Ancak displayed financial percentage değiştirilemez.

---

## 12. AlertStatus

Backend string enum değerlerini güvenli biçimde eşleştir:

- Normal
- Warning
- Exceeded

UI:

Normal:
- Success / green
- `Normal`

Warning:
- Warning / amber
- `Kritik` veya `Limite Yakın`

Exceeded:
- Error / red
- `Limit Aşıldı`

Sadece renkle bilgi verme; text etiketi de göster.

Bilinmeyen enum değeri geldiğinde uygulama çökmemelidir.

Kontrollü fallback kullan.

## 17. Month/Year validation

Month:

- 1–12

Year:

- 2000–2100

UI picker kullan.

Serbest text gerekmez.

---

## 18. Duplicate Budget davranışı

Backend aynı:

UserId + CategoryId + Month + Year

için duplicate Budget'a izin vermemektedir.

Backend 409 Conflict döndürdüğünde kullanıcı dostu mesaj göster.

Örneğin:

`Bu kategori için seçilen dönemde zaten bir bütçe bulunuyor.`

Raw backend exception veya PostgreSQL unique constraint detayı gösterme.

---

## 19. Başarılı create

POST başarılı olduğunda:

- form kapanabilir
- Budget listesi yenilenmeli
- oluşturulan Budget seçili dönem içindeyse görünmelidir
- kısa success feedback verilebilir

Double-submit engelle.

## 20. Budget güncelleme

Budget kartında:

- edit aksiyonu

bulunabilir.

Edit ekranı veya bottom sheet aç.

- Category → read-only
- Month → read-only
- Year → read-only
- LimitAmount → editable

Backend kuralı gereği yalnızca LimitAmount değiştirilebilir.

## 21. Update request

Kullanıcı yeni limit girdikten sonra:

`PUT /api/budgets/{id}`

çağrısı yap.

Request yalnızca:

`limitAmount`

içermelidir.

Category, Month veya Year request'e eklenmemelidir.

## 22. Update success

Update başarılı olduğunda backend'den dönen BudgetResponse kullan.

Mobil:

- SpentAmount hesaplamamalı
- UsagePercent hesaplamamalı
- AlertStatus hesaplamamalı

Güncellenen backend response'u göster veya listeyi refresh et.

---

## 23. Update 404

Backend 404 döndürürse ownership detayı açıklama.

Sade mesaj:

`Bütçe kaydı bulunamadı veya artık mevcut değil.`

Ardından liste refresh edilebilir.

---

- İptal
- Sil

`DELETE /api/budgets/{id}`

Gerçek backend'e bağımlı test oluşturma.

- Budget response doğru parse edilir.
- AlertStatus Normal parse edilir.
- Warning parse edilir.
- Exceeded parse edilir.
- UsagePercent > 100 korunur.
- Create request UserId içermez.
- Update request yalnızca LimitAmount içerir.
- Service doğru endpointleri kullanır.

### List

- Loading state.
- Error + retry.
- Empty state.
- Budget listesi render.
- Selected month/year filtreleme.
- Başka dönem Budget gösterilmez.
- Normal UI doğru.
- Warning UI doğru.
- Exceeded UI doğru.
- `%135` text korunur.
- Progress visual clamp edilir.

### Create

- Category zorunlu.
- Limit boş reddedilir.
- Limit 0 reddedilir.
- Negatif limit reddedilir.
- Month/year doğru request'e gider.
- UserId gönderilmez.

### Refresh
