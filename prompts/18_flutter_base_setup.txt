SmartBudget AI mobil uygulamasının sağlam, sade ve mevcut backend ile uyumlu temelini oluşturmak.

## Çok Önemli Source-of-Truth Önceliği

Backend ve proje dokümanları özellikler açısından ana doğruluk kaynağıdır.

Stitch tasarımları yalnızca görsel/UX referansıdır.

Stitch HTML çıktısını birebir özellik kaynağı olarak kabul etme.

Stitch tasarımında backend'de olmayan bir özellik görünüyorsa onu Flutter'a taşıma.

Özellikle:

- Fatura Trendleri ekranında AI gelecek fatura tahmini gösterme.
- Profil ekranında isim gösterme.
- Profil ekranında Pro/Premium üyelik gösterme.
- Profil ekranında hesap ayarları gösterme.
- Profil yalnızca authenticated kullanıcının email adresi ve Çıkış Yap aksiyonunu içermelidir.
- Google/Apple login ekleme.
- Bildirim özelliği ekleme.
- Bill payment status ekleme.
- Yeni backend özelliği uydurma.

Flutter + Dart kullan.

Mümkün olduğunca güncel ve sade Flutter yaklaşımı kullan.

Bu proje MVP olduğu için gereksiz architecture framework ekleme.

Şunları ekleme:

- BLoC
- Redux
- GetX
- Riverpod
- injectable
- code generation ağırlıklı yapı
- Clean Architecture katmanlarını gereksiz yere çoğaltma

State management için Flutter'ın temel imkanları yeterliyse onları kullan.

Gerekirse küçük ve sınırlı ChangeNotifier yaklaşımı kullanılabilir.

## 1. Flutter Projesini Oluştur

Eğer mobile altında Flutter projesi yoksa oluştur.

Android ve iOS hedeflerini destekle.

Web veya desktop bu MVP için gerekli değildir.

Project/package isimlerini mevcut SmartBudget projesiyle tutarlı seç.

## 2. Gerekli Paketler

Yalnızca gerçekten gerekli minimum paketleri ekle.

Beklenen temel ihtiyaçlar:

- HTTP API iletişimi
- JWT secure storage

Tercih:

- dio veya http paketlerinden yalnızca biri
- flutter_secure_storage

İkisini birden ekleme.

Bu aşamada chart, animation veya ağır UI paketlerini henüz ekleme.

Eklenen her paketi raporda açıkla.

## 3. API Configuration

Backend base URL tek bir merkezi config üzerinden yönetilmelidir.

Örneğin:

ApiConfig.baseUrl

Hardcoded endpoint URL'lerini farklı screen dosyalarına dağıtma.

Development için base URL configuration üzerinden değiştirilebilir olmalıdır.

Android emulator için localhost problemini dikkate al.

Ancak gerçek deployment URL'si uydurma.

## 4. API Client

Merkezi sade bir ApiClient oluştur.

Sorumlulukları:

- GET
- POST
- PUT
- DELETE
- JSON encode/decode
- Authorization header ekleme
- temel timeout
- kontrollü API error handling

JWT varsa:

Authorization: Bearer <token>

otomatik eklenmelidir.

API client:

- token'ı loglamamalı
- password loglamamalı
- raw backend stack trace göstermemeli

Gereksiz generic networking framework oluşturma.

## 5. Secure Storage

JWT access token flutter_secure_storage ile saklanmalıdır.

SharedPreferences içine JWT koyma.

En az:

- saveToken
- readToken
- deleteToken

davranışlarını destekle.

Gerekirse authenticated kullanıcının email adresini sade biçimde saklama/elde etme yaklaşımı oluştur.

Ancak password saklama.

## 6. Authentication Model ve Service

Mevcut backend Auth endpointlerini inceleyerek Flutter model/service yapısını oluştur.

Login ve Register request/response modelleri backend sözleşmesiyle birebir uyumlu olmalıdır.

Endpoint path veya JSON field isimlerini tahmin etme.

Mevcut backend controller/DTO'larını okuyarak belirle.

AuthService en az:

- register
- login
- logout
- mevcut token var mı kontrolü

davranışlarını sağlamalıdır.

Başarılı login:

- access token secure storage'a yazılmalı
- kullanıcı authenticated state'e geçmeli

Logout:

- token silinmeli
- auth state temizlenmeli

## 7. App Startup / Auth State

Uygulama açıldığında:

- secure storage'daki token kontrol edilmeli

Token varsa:

- authenticated ana yapıya yönlendir

Token yoksa:

- Login ekranına yönlendir

Bu aşamada refresh token mekanizması oluşturma.

Backend MVP'de refresh token yoktur.

JWT'nin gerçek geçerliliğinin backend tarafından 401 ile kontrol edileceğini unutma.

## 8. 401 / Session Expired Davranışı

API 401 döndürürse:

- token temizlenebilmeli
- kullanıcı Login ekranına yönlendirilebilmeli
- teknik olmayan sade mesaj gösterilmeli

Örnek semantik:

"Oturumunuz sona erdi. Lütfen tekrar giriş yapın."

Bu davranışı merkezi API/auth yaklaşımına uygun şekilde tasarla.

Screen'lerin her birine ayrı ayrı kopyalama.
