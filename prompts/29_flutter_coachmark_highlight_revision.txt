Önce PROJECT.md ve docs/DESIGN.md dosyalarını oku.

Ardından mevcut Flutter interactive tutorial/walkthrough implementasyonunu incele.

Manuel emulator testinde mevcut walkthrough UX'inin yetersiz olduğu görüldü.

## Mevcut Problem

Tutorial şu anda gerçek ekranı arka planda gösteriyor ancak:

- tüm ekran belirgin şekilde karartılıyor
- tutorial popup/card çok büyük
- ekranın önemli bölümünü kaplıyor
- anlatılan gerçek UI elemanı highlight edilmiyor
- kullanıcı hangi butonun/alanın anlatıldığını net göremiyor

Bu nedenle mevcut yapı gerçek bir coach-mark/walkthrough gibi çalışmıyor.

Bu görevde tutorial'ı daha küçük, gerçek UI öğelerini vurgulayan bir coach-mark yapısına revize et.

Backend değiştirme.
Database değiştirme.
Yeni API endpoint ekleme.
Yeni Flutter package ekleme.

---

# 1. Temel UX Hedefi

Tutorial sırasında kullanıcı gerçek uygulama ekranını mümkün olduğunca net görmelidir.

Büyük full-screen modal kullanma.

Tutorial açıklama kartı:

- kompakt olmalı
- yalnızca gerekli metin ve navigation kontrollerini içermeli
- mümkünse ekranın alt veya üst bölümünde yer almalı
- anlatılan UI elemanını kapatmamalı

Arka plan:

- tamamen koyu/gri hale getirilmemeli
- mümkünse hiç karartılmasın
- gerekiyorsa sadece çok hafif scrim kullanılabilir

Amaç:
kullanıcının gerçek ekranı net biçimde görmesi.

---

# 2. Gerçek UI Elemanlarını Highlight Et

Her tutorial adımında anlatılan gerçek UI elemanı görsel olarak vurgulanmalıdır.

Üçüncü parti coach-mark package kullanma.

Mevcut Flutter widget'larıyla sade bir çözüm üret.

Tercih edilen yaklaşım:

- hedef widget'lara GlobalKey ver
- RenderBox üzerinden ekrandaki position/size bilgisini al
- Overlay/Stack içinde hedef alanın çevresine belirgin bir border/highlight çiz
- tutorial kartını hedefi kapatmayacak uygun bölgeye yerleştir

Alternatif olarak mevcut architecture içinde daha güvenilir basit bir highlight yaklaşımı varsa onu kullan.

Ama coordinate değerlerini hard-code etme.

Farklı ekran boyutlarında çalışmalı.

---

# 3. Highlight Görünümü

Hedef alanın çevresinde:

- DESIGN.md primary rengiyle ince border
- hafif glow veya shadow
- 8-12 px padding
- rounded rectangle

kullanılabilir.

Aşırı animasyon yapma.

Highlight edilen UI elemanı ekranın geri kalanından rahatça ayırt edilmelidir.

---

# 4. Arka Plan Scrim

Mevcut güçlü karartmayı kaldır.

Eğer scrim kullanılacaksa:

- çok hafif olmalı
- gerçek ekran okunabilir kalmalı

İdeal olarak hedeflenen alan tamamen normal/parlak kalmalıdır.

Mümkünse overlay içinde hedef alanın üstüne karartma uygulanmasın.

Ancak karmaşık custom clip çözümü uygulamayı kıracaksa:
- tüm ekranı karartmak yerine scrim'i minimum seviyede tut
- target border/highlight ile hedefi belirginleştir

Basitlik ve stabilite önceliklidir.

---

# 5. Tutorial Kart Boyutu

Mevcut büyük modalı küçült.

Tutorial card:

- ekran yüksekliğinin büyük bölümünü kaplamamalı
- yalnızca başlık + kısa metin + step indicator + navigation kontrollerini içermeli

Önerilen yapı:

Başlık
1-2 kısa paragraf
3 / 6
Geri | İleri

Kartta gereksiz boş alan bırakma.

Özellikle mevcut ekran görüntüsündeki gibi ekranın yaklaşık yarısından fazlasını kaplayan boş beyaz alan olmamalıdır.

Metin uzun gelirse içerik kadar büyüsün.

# 8. Step 3 — AI Kategori Önerisi

İşlemler sekmesinde kal.

AI özelliğinin gerçek kullanım yerine en yakın UI elemanını highlight et.

Tercihen:
- İşlem Ekle/Gider Ekle butonu
veya
- gider oluşturma akışındaki AI kategori önerisi kontrolü, eğer bunu sadece görsel şekilde göstermek güvenli ve kolay ise.

Ama:

- formu otomatik submit etme
- backend çağrısı yapma
- AI endpoint çağırma
- kayıt oluşturma

Tutorial text:

Başlık:
"AI ile Kategori Önerisi"

Metin:
"Gider açıklamanıza göre AI'dan kategori önerisi alabilirsiniz. Öneriyi kabul etmek veya değiştirmek sizin kontrolünüzdedir."

Eğer AI kontrolü form açılmadan görünmüyorsa karmaşık state üretme.
Bu durumda İşlem Ekle butonunu highlight etmek yeterlidir.

# 13. `?` Yardım Butonu

Mevcut sağ üst `?` butonu kesinlikle korunmalıdır.

- Tooltip: Yardım
- authenticated tüm ana sekmelerde erişilebilir

`?` butonuna basılınca walkthrough step 1'den başlamalıdır.

Tutorial zaten açıksa ikinci overlay oluşturma.

---

# 14. Interaction Safety

Tutorial sırasında highlighted element kullanıcıya gösterilmelidir ancak yanlışlıkla gerçek finansal işlem yapılması engellenmelidir.

Tercihen overlay pointer input'u yakalasın.

Yani:
- highlighted buton görsel olarak görünür
- fakat kullanıcı tutorial sırasında o butona basıp kayıt akışını yanlışlıkla başlatamaz

Sadece tutorial navigation kontrolleri aktif olabilir.

Ancak teknik olarak mevcut yapıda bu aşırı karmaşıksa en güvenli basit çözümü uygula.

---

# 15. Responsive Davranış

Hard-coded pixel coordinate kullanma.

Target widget konumu gerçek RenderBox üzerinden belirlenmeli veya mevcut layout ile güvenli şekilde ilişkilendirilmelidir.

Kontrol et:

- küçük Android ekran
- normal Android emulator

Tutorial card:
- target'ı kapatmamalı
- ekrandan taşmamalı

Eğer target ekranın altındaysa tutorial card üstte konumlanabilir.
Target üstteyse card altta konumlanabilir.

Basit automatic positioning mantığı yeterlidir.
