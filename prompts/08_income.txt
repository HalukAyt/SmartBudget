Önce PROJECT.md, docs/ANALIZ.md ve docs/TEKNIK_MIMARI_TASLAK.md dosyalarını oku.

Bu dosyalar projenin source of truth dokümanlarıdır.

SmartBudget AI projesinde yalnızca Income özelliğini geliştir.

Mevcut Authentication/JWT, Category ve Expense yapıları korunmalıdır.

Bu aşamada Budget, Bill, Dashboard ve AI özelliklerine geçme.

## Yapılacaklar

1. Income DTO'larını oluştur.

En az:

- CreateIncomeRequest
- IncomeResponse
- IncomeListItemResponse

oluştur.

CreateIncomeRequest alanları:

- Amount
- Description
- Date

Kurallar:

- UserId request içinde bulunmamalıdır.
- Amount > 0 olmalıdır.
- Description opsiyoneldir.
- Description verilmişse trim edilmelidir.
- Description yalnızca whitespace ise null/boş değer gibi ele alınmalıdır.
- Date zorunlu olmalıdır.

2. IncomeService oluştur.

IncomeService Entity Framework Core AppDbContext'i doğrudan kullanmalıdır.

Generic Repository veya Unit of Work oluşturma.

IncomeService aşağıdaki işlerden sorumlu olmalıdır:

### Income oluşturma

- authenticatedUserId parametresi al.
- UserId request'ten alma.
- Amount > 0 doğrula.
- Description varsa trim et.
- Description boş/whitespace ise null olarak saklanabilir.
- Yeni Guid oluştur.
- UserId alanını authenticatedUserId değerinden ata.
- CreatedAt UTC oluştur.
- Date alanını tarih-only mantığıyla kullan.
- Income kaydını veritabanına kaydet.
- Entity yerine IncomeResponse döndür.

### Income listesi

Authenticated kullanıcının yalnızca kendi Income kayıtlarını döndür.

Başka kullanıcı kayıtları hiçbir koşulda listeye karışmamalıdır.

AsNoTracking ve DTO projection kullan.

Liste sıralamasını deterministik yap.

Tercihen:

- Date descending
- aynı Date için CreatedAt descending
- aynı CreatedAt için Id descending

kullan.

### Income silme

DELETE /api/incomes/{id}

- Kayıt hem Income Id hem authenticated UserId ile aranmalıdır.
- Önce yalnızca Id ile kayıt bulup sonra ownership kontrolü yapma.
- Başka kullanıcıya ait veya bulunmayan kayıt için aynı güvenli 404 yaklaşımını kullan.
- Kullanıcı yalnızca kendi Income kaydını silebilmelidir.
- Başarılı silmede 204 No Content dön.

3. IncomesController oluştur.

Endpointler:

GET /api/incomes
POST /api/incomes
DELETE /api/incomes/{id}

Tüm endpointler authentication gerektirmelidir.

Controller ince olmalıdır.

Controller:

- CurrentUserAccessor üzerinden authenticated user id almalı,
- ilgili IncomeService metodunu çağırmalı,
- uygun HTTP response üretmeli.

Business logic Controller içine yazılmamalıdır.

4. Mevcut CurrentUserAccessor yapısını kullan.

Yeni user id okuma mekanizması oluşturma.

Request body, query veya route üzerinden UserId kabul etme.

5. HTTP hata davranışları

Beklenen durumlar:

- Amount <= 0 → 400
- Date eksik/geçersiz → 400
- Authentication yok/geçersiz → 401
- Başka kullanıcıya ait Income silme isteği → 404
- Bulunmayan Income → 404
- Beklenmeyen hata → güvenli 500

Production response'larında stack trace gösterme.

Mevcut merkezi exception/error handling yaklaşımını kullan.

6. Response yapısı

IncomeResponse içinde en az:

- Id
- Amount
- Description
- Date
- CreatedAt

bulunmalıdır.

Entity doğrudan serialize edilmemelidir.

7. Testler oluştur.

En az aşağıdaki davranışları test et:

- Başarılı Income oluşturma
- UserId request'ten değil authenticated user id'den atanıyor
- Amount 0 reddediliyor
- Negatif Amount reddediliyor
- Description null kabul ediliyor
- Description boş string kabul ediliyor ve kontrollü şekilde normalize ediliyor
- Description whitespace kontrollü şekilde normalize ediliyor
- Description trim ediliyor
- Date zorunlu
- Income listesi yalnızca authenticated kullanıcı kayıtlarını döndürüyor
- Liste sıralaması deterministik
- Başka kullanıcı kayıtları listeye karışmıyor
- Income delete yalnızca sahibine izin veriyor
- Başka kullanıcı Income delete isteğinde 404
- Bulunmayan Income delete isteğinde 404
- Silinen Income artık listede görünmüyor
- API response entity yerine DTO kullanıyor

Mümkün olduğunca mevcut test altyapısını kullan.

8. Build ve tüm testleri çalıştır.

Mevcut Authentication ve Category/Expense testleri de geçmeye devam etmelidir.
